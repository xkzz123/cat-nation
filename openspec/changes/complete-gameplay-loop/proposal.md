# Proposal：补齐地图版游戏进程闭环

## Why

当前地图版已经能完成采集、建设、人口分工、科研和存档，但玩家从“知道下一项科技”走向“理解当前阶段、处理危机、使用高级系统、完成一轮并开始下一轮”的过程仍不连贯。建议优先补齐这些连接，让玩家持续知道当前目标、受阻原因、可执行动作和本轮收获。

Kittens Game 是持续经营和转生的增量游戏。本提案以“阶段达成 → 本轮结算 → 自愿转生 → 新周目承接”构成闭环，不新增强制通关或人口归零后的 Game Over。

## Research / 调研

### 方法与基线

2026-11-08，静态审查 `feature-v1` 提交 `5fd9d4b` 的地图、原版引擎、本地存档适配、测试和项目文档；以已有试玩记录交叉核对。当前 `main` 只有初始 README，功能评估以 `feature-v1` 为准。此次未进行新的浏览器全流程试玩，历史测试通过数不作为本轮执行结果。

仓库没有已有的 OpenSpec 目录。本次按官方 spec-driven 模板建立 proposal、design、tasks 和 capability delta specs，尚未归档为已实现规范。

### 玩家旅程与证据

| 流程 | 已有能力与证据（相对仓库根目录） | 缺口与影响 | 判断与优先级 |
| --- | --- | --- | --- |
| 进入与继续 | `game/local-client.js` 初始加载、`README.md` 磁盘优先恢复说明 | 地图缺少载入结果与当前发展状态的统一回顾，旧档回来仍需自行找方向 | 入口整合，P1 |
| 第一轮开局 | `game/map/app.js:renderGoal` 提供食物→住房→图书馆的整段提示；`bridge.js` 有真实购买与分工 | 没有逐步目标完成反馈；读过说明并不等于完成动作，新手难定位当前卡点 | 引导补齐，P0 |
| 生存与危机恢复 | `app.js:refresh` 对猫薄荷净产出为负提示；村庄面板展示人口、空闲和幸福度 | 警告未给出按当前速度的耗尽时间、具体供粮入口及危机解除反馈；当前负产出不等于必然死亡 | 引导补齐，P0 |
| 地面经营→工业 | `techPlan` 使用科技优先级和前置关系，`renderGoal` 检查库存与容量；工坊支持合成与升级 | 科技解锁后没有“建设施、安排岗位、落实生产”的明确目标承接；待合成、岗位缺失、地块已满不在统一阻塞解释内 | 目标模型扩展，P0 |
| 贸易、宗教、太空、政策与时间 | `game/map/shell.html` 明示高级功能由原版界面管理；`app.js:setMode` 共享游戏实例；`game/js/` 保留对应系统 | 入口是通用切换，缺少按阶段说明、定位目标页、操作后返回目标的桥接 | 可发现性与导航补齐，P1；机制本身已存在 |
| 暂停、退出与回来 | `local-client.js` 有暂停、现实时间自动保存、离页保存；README 说明离线沿用原版 | 没有统一解释“本次回来发生了什么、现在要处理什么”；离线收益和人口变化呈现不足 | 回归摘要，P1；离线算法需运行核验 |
| 本轮结束与转生 | `app.js` 转生按钮直调 `game.reset()`；`game.js:reset` 已有确认和人口阈值提示，`getResetPrestige` 计算收益；`local-client.js:resetAutomatic` 先备份再保存结果 | 缺少集中展示保留/重置项目、本轮回顾和新周目目标。失败分支仅提示恢复，需验证失败发生时内存与磁盘是否一致及能否安全重试 | 生命周期补齐，P0；不另写收益公式 |
| 挑战与长线目标 | `game/js/challenges.js` 与原版界面保留挑战；`techPlan` 无目标时显示继续高级系统 | 科技推荐结束不等于游戏结束；缺少长线分支选择、挑战进行中/完成后的承接 | 目标分流，P1 |
| 存档异常与恢复 | `local-client.js:canWrite/replace`、`tests/storage.test.mjs` 有冲突与恢复保护 | 游戏目标需要服从只读/冲突状态，恢复旧档后不能沿用未来阶段的完成标记 | 集成约束，P0 |
| 后期完整性验证 | `docs/试玩与修复记录.md` 主要覆盖开局、地面经营、科研和本地存档，明确未逐局验证太空与全部挑战；`game/test/game.test.js` 有部分宗教与转生测试 | 不能据现有覆盖认定后期完整；需要阶段存档和跨系统旅程验证 | 验收补齐，P1 |

### 调研结论

最先解决的四个断点是：开局缺少动作级承接、研究完成后目标脱节、危机出现后缺少恢复路径、转生前后缺少可理解的结算与接续。高级系统以可定位的原版入口接入，优先形成完整旅程，再决定哪些系统值得逐步迁入地图。

不建议先新增战斗、剧情结局或另一套经济。这些会扩大内容量，无法直接修复现有进程的上述断点。固定 61 格地图与独立建筑槽位对后期规模的影响也应专项验证：目标系统必须解释空间阻塞，并提供待安置与原版建设的现行规则提示，不能承诺无限扩张。

## What Changes

1. P0：建立从真实游戏状态推导的阶段与行动目标，覆盖采集、稳定供粮、居住、人口分工、科研、工坊与工业基础；自由经营可随时退出引导。
2. P0：统一解释目标阻塞，包括解锁、容量、地块槽位、资源、合成和岗位，并提供具体操作入口；研究完成后衔接生产动作。
3. P0：新增危机恢复卡，展示当前粮食风险、耗尽估计、建议动作和解除反馈，独立于玩家主动追踪目标。
4. P0：补齐转生预览、可靠写入与失败恢复、新周目目标和一次性本轮回顾；继续复用原版规则和本地备份。
5. P1：接入高级系统目录，解释开放条件、定位原版功能、返回后刷新状态；完成科技路线后允许选择太空、信仰、时间、转生或挑战方向。
6. P1：进入游戏后显示载入/回归摘要；恢复和导入时以载入状态重新计算目标，支持旧档和离线返回。
7. 建立从新档到转生再到挑战的场景验收矩阵；功能完成后再归档规范。

## Capabilities

### New Capabilities

- `progression-guidance`：阶段、行动目标、阻塞解释与高级系统桥接。
- `survival-recovery`：粮食危机识别、可操作恢复与解除反馈。
- `run-lifecycle`：转生预览、安全提交、本轮回顾与新周目接续。
- `session-reentry`：载入结果、回归摘要与旧档/恢复兼容。

### Modified Capabilities

无。当前不存在已归档 OpenSpec capability，新增规范描述拟增加的可见行为，不将现有代码伪装成已有规格。

## Impact

主要影响 `game/map/app.js`、`shell.html`、`style.css`、`bridge.js` 和 `game/local-client.js`；计划增加小型阶段规则模块。原版 `game.js`、科技、宗教、太空和挑战管理器继续负责规则与收益。必要的原版页定位适配集中在 bridge，避免散落 DOM 选择器。

存档增加可选的流程展示元数据，兼容缺失字段的旧档；经济存档和 `hexMap` 保持现有职责。转生失败恢复需对现有本地保存链补充验证，服务端接口是否变更取决于现有幂等保证核验结果，不预设新增接口。

交付顺序：先 P0 形成首轮闭环，再实施 P1 的高级系统和回归体验。实现与验证状态见 `tasks.md` 和 `review.md`；浏览器及用户验收完成后再归档。
